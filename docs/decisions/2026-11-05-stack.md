# Stack and log readers · 5 Nov 2026

**Decided (Diego, SR-1):** repo `AIwithDiego/session-receipts` (private until the showcase, SR-8; public from SR-8, 16 Nov 2026); Python 3 standard library only; receipts written to `~/.session-receipts/` on this Mac; fuzzy rules judged by the agent already running the skill (no API key); no hosting, database, domain, email or paid tools.

**Why Python, stdlib only:** nothing to install in either tool, runs anywhere Claude Code or Codex runs, and the work is just reading JSONL.

**Readers (SR-2):**
- Claude Code: `~/.claude/projects/<project>/<session>.jsonl`, subagents in `<session>/subagents/*.jsonl` folded into the parent. Prompts = user entries that are not tool results, meta or harness tags. Tokens counted once per API message id (each message is logged once per content block). Blocked actions = error results that read like a hook, permission, sandbox or user refusal, plus `permissionDecision.decision == "reject"`.
- Codex: `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`. Reads `item_completed` events, not raw model calls (shell commands are wrapped in JavaScript there). `input_tokens` includes cached tokens, so input = input minus cached. Unknown step types and older files without `item_completed` are noted on the session, never guessed.
- Every fact keeps its log file and line number, the proof for rules (SR-4).

**Known gap:** scheduled runs (e.g. an agent that refreshes a dashboard every ~10 min) log exactly like typed prompts. The day view groups them by same project + same prompt.

**History archive (SR-9):** Claude Code deletes logs untouched for 30 days (`cleanupPeriodDays`). We keep that default, since raw logs can hold secrets, and archive the redacted summary and receipt instead: `~/.session-receipts/archive/<YYYY-MM>/<id>.json.gz`, folder 0700, files 0600, about 8 MB for four months. Archived text is redacted again on each build. A live read replaces its archived copy unless the copy is fuller (a `--days` build sees only part of a long session).

**Live page (SR-10, Diego):** the dashboard is served at http://localhost:4747 by `python3 -m receipts serve` (standard library `http.server`), kept running by a launchd login item. It keeps each log's parsed receipt in memory keyed by file size and mtime (plus subagent files), so a refresh re-reads only what changed. Because a website open in the browser can send requests to localhost, the server binds 127.0.0.1, accepts only `localhost`/`127.0.0.1` Host headers (DNS rebinding), refuses cross-site `Sec-Fetch-Site` and foreign `Origin`, and serves data as `application/json` with `nosniff` (never as a script another page could include). The static build stays for the packaged skill (SR-5).

**Rules (SR-4):** plain-language rules in `~/.session-receipts/rules.md` (outside the repo: they are personal). The plain text is what the receipt shows; an optional check in backticks is what makes it provable. We chose explicit checks over guessing a check from the wording, because a receipt is evidence and a guessed check would be a claim nobody wrote down. Statuses: broken (went through), tried (blocked or failed), kept (with what was checked, and the prompt that allowed it for "unless asked"), not judged yet. Secret-file printing is judged per statement: values captured into a variable, names only, counts, masked output and public `NEXT_PUBLIC_`/`VITE_` values don't count. Editing the rules file re-checks every live session on the next refresh; archived receipts keep the result they were saved with.

**Public release (SR-8, 16 Nov 2026):** published as free, non-monetised open source, so the EU Cyber Resilience Act does not apply (recital 18). That changes if it is ever sold, sold with support, or shipped inside a paid client deliverable: review the CRA then. No telemetry and no update checks, ever: AIwithDiego stays neither controller nor processor for anyone's use of it.
